# ADR-003: Event-Driven Architecture
- Status: Active

**In the context of**
- *Notification Service*, *Analytics Service*, *Audit Service*

**Facing the need for**
- reacting asynchronously to domain events without introducing tight runtime coupling between services

**We decided for**
- using an Event-Driven Architecture

**Achieving**
- a loosely coupled architecture that supports asynchronous processing, independent scaling of consumers, and easy extension with new event handlers

**Accepting that**
- eventual consistency between services
- more complex debugging and tracing
- more challenging event schema evolution and versioning
- additional operational complexity around messaging infrastructure
