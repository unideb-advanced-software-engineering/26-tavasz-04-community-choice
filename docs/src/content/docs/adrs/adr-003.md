# ADR-003: Event-Driven Architecture
- Státusz: Aktív

**In the context of**
- a *Notification Service*, az *Audit Service* és a médiafeldolgozási pipeline tervezésekor, ahol ezek a komponensek domain eseményekre reagálnak, de nem léphetnek be a szavazási kérések szinkron feldolgozási útjába

**Facing the need for**
- olyan kommunikációs mintára, amellyel a *Voting Service* és a *Campaign & Admin Service* képes domain eseményeket kibocsátani anélkül, hogy tudnia kellene, ki és mikor fogyasztja azokat — a szoros runtime csatolás auditnaplózásnál és értesítéseknél elfogadhatatlan, mert közvetlen hatással lenne a szavazási kérések kiszolgálási idejére

**We decided for**
- Event-Driven Architecture alkalmazása Apache Kafka üzenetbrókerrel ([ADR-004](ADR-004.md)): a *Voting Service* és a *Campaign & Admin Service* domain eseményeket bocsát ki, amelyeket a *Notification Service*, az *Audit Service* és a *Media Worker* egymástól teljesen függetlenül, saját Kafka consumer groupon keresztül fogyaszt

**Achieving**
- a *Notification Service* és az *Audit Service* meghibásodása vagy lassulása nem gyűrűzik vissza a szavazási folyamatba — a felhasználói kérések kiszolgálási ideje nem függhet az auditnaplózás vagy az értesítés-küldés sebességétől
- az *Audit Service* Kafka offsetje révén visszajátszhatja az eseménytörténetet újraindulás vagy adatvesztés esetén, ami biztosítja a napló teljességét
- új fogyasztók (pl. egy jövőbeli Analytics Service) a meglévő producerek módosítása nélkül csatlakozhatnak az eseményfolyamhoz
- a médiafeldolgozási pipeline teljesen leválik a webes szálakról: videófeltöltés után a tömörítés aszinkron, a *Media Worker*-en fut

**Accepting that**
- az aszinkron feldolgozás eventual consistency-t jelent: az auditnaplóba kerülés nem azonnali, néhány másodperces késéssel számolni kell
- az elosztott eseményfolyam hibakeresése és nyomkövetése (distributed tracing) összetettebb, mint egy szinkron hívássorozaté
- az esemény-séma evolúciója körültekintést igényel: egy már publikált eseménytípus mezőinek eltávolítása visszafelé inkompatibilis változtatás, ami a fogyasztókat is érinti
- a Kafka infrastruktúra üzemeltetési többletterhelést jelent (lásd [ADR-004](ADR-004.md))
